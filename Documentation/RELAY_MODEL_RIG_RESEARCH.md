# Relay model, rig and movement research

## Research → prototype decisions

The Backrooms reference is used for atmosphere and spatial behaviour, not for
copying a film creature or importing protected assets. The Level 0 description
centres the experience on a yellow, damp carpet labyrinth and an oppressive
fluorescent buzz. The film interviews likewise describe the hum as a designed,
repeated sound layer. That means the Relay should be felt through silhouette,
movement and footfall before it is fully readable.

Unity's Animation Rigging documentation describes a rig as a bone hierarchy
plus constraints evaluated by animation jobs. Unity's Animator documentation
describes an Animator Controller as a state machine that selects clips and
transitions. For this WebGL functional prototype, the same state contract is
implemented with explicit bone transforms and a deterministic procedural driver:
it avoids a large imported character, keeps the model editable in the Scene
hierarchy, and leaves a clean replacement point for a skinned FBX and Animator
Controller later.

Unity's WebGL guidance notes that skinning is multi-threaded/SIMD-optimised and
that vertex compression and unused-mesh stripping reduce build cost. The
prototype therefore uses a small primitive assembly now, with no runtime
allocations during animation and no cloth, hair or dynamic physics. If a
production mesh is added, cap it at 24–36 bones and four influences per vertex.

## Model language

`The Relay` is an original tall, hunched silhouette:

- blank pale head with one narrow dark face void;
- compressed chest and uneven shoulder line so the pose never reads as a
  neutral humanoid mannequin;
- long segmented arms ending in blocky hands;
- narrow two-part legs and oversized feet for a readable carpet impact;
- charcoal body, warm grey head and muted yellow detail material so a doorway
  or flicker can reveal the creature without a bright character shader.

The hierarchy is visible under `RELAY RIG / bones`:

`root → pelvis → spine → chest → neck → head`, with separate upper/lower arm,
hand, thigh, shin and foot chains on both sides.

## Motion state contract

| Encounter state | Rig state | Movement cue |
| --- | --- | --- |
| Listen / Search | `IdleListen` | off-axis head scan, small spine sway |
| Hunt | `Walk` | restrained alternating stride |
| Chase | `Run` | larger stride, faster arms and stronger pelvis bob |
| BreakDoor | `BreakDoor` | crouched chest, both forearms load forward |
| Caught / recovery hook | `Stagger` | short unstable root shake |

`FrontRoomsRelayRig.TickAnimation` is the single runtime entry point. The
existing encounter state machine remains authoritative; the rig only turns its
state and movement amount into bone rotations. That keeps timing and gameplay
logic independent from the visual implementation.

## Foley landing

Level 0 carpet is treated as a damp, low-frequency supermarket carpet surface.
Player steps use a lighter rounded impact and short fibre release. Relay steps
use a heavier sub transient, longer fibre tail and the existing low-pass filter
so the creature remains audible through walls without sounding like the player.
Six seeded variants per actor/surface/run state prevent immediate repeats. The
same `FrontRoomsFoleySurface.Carpet` bank is used by Lobby and Shift.

## Editable implementation

- `Assets/Scripts/FrontRoomsRelayRig.cs` builds the model and bone hierarchy,
  exposes preview state/speed fields, and drives the four encounter motions.
- `Assets/Scripts/FrontRooms3DGame.cs` attaches the rig to both the serialized
  Hunter and the streamed Relay, then maps `HunterState`/`StreamThreatState`
  into rig states.
- `Assets/Scripts/FrontRoomsFoley.cs` composes carpet impact, fibre texture and
  cloth layers separately for Player and Hunter.

No build output is regenerated by this pass. The Unity scene remains the
editable source of truth.
